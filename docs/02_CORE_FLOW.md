## 1. 하루 기록 생성 흐름

유저가 홈 화면에서 특정 루틴에 오늘의 기록을 남기는 **가장 핵심 흐름**.

| 단계 | 사용자 행동 | 시스템 반응 | 다음 화면 |
|------|------------|-----------|---------|
| 1 | 홈 화면 진입 | 오늘 날짜 기준 "오늘의 기록"과 "기록 루틴" 영역 표시 | 홈 |
| 2 | 특정 루틴 카드의 `오늘의 기록 시작하기` 탭 | 해당 루틴 ID를 가진 기록 작성 화면으로 진입 | 기록 작성 |
| 3 | 마이크 아이콘 또는 텍스트 입력창 선택 | 음성: 녹음 시작 (중지 버튼으로 전환) / 텍스트: 키보드 표시 | 기록 작성 (입력 중) |
| 4 | 입력 완료 (중지 or 타이핑 완료) | 음성의 경우 Whisper 호출 → 변환된 텍스트 하단 채팅창에 표시 | 기록 작성 (검토) |
| 5 | 변환/입력된 텍스트 검토, 필요시 직접 수정 | 텍스트 편집 가능 상태 유지 | 기록 작성 (검토) |
| 6 | 전송 버튼(↑) 탭 | "열심히 요약하는 중..." 로딩 표시, Claude API 호출 | 기록 작성 (분석 중) |
| 7 | 대기 | Claude 응답 수신 → JSON 파싱 → 카테고리별 카드 렌더링 | 기록지 생성 결과 |
| 8 | `기록 완료` 버튼 탭 | DB에 Record 생성(저장), 저장 완료 화면 표시 | 저장 완료 |
| 9 | `홈으로` 또는 `확인하기` 중 선택 | 홈으로: 홈 복귀 / 확인하기: 기록지 상세 뷰어 | 홈 또는 기록지 뷰어 |

**핵심 규칙**
- 8단계에서 이미 DB 저장 완료. 이후 조작은 UPDATE.
- 같은 루틴을 하루 여러 번 기록 시 매번 새 Record 생성 (중복 체크 없음).
- 6단계 이후 뒤로가기 금지 (분석 중 이탈 방지).
- 기록의 `recorded_date`는 **현재 조회 중인 날짜** 기준 (홈에서 캘린더로 과거 날짜 이동 후 기록 시 → 그 날짜로 저장).

## 2. 기록 조회 흐름

이미 작성한 기록을 확인하는 흐름. 오늘 기록과 과거 기록으로 나뉜다.

### 2-A. 오늘의 기록 조회

| 단계 | 사용자 행동 | 시스템 반응 | 다음 화면 |
|------|------------|-----------|---------|
| 1 | 홈 화면 진입 | 오늘의 기록 영역에 오늘 작성된 Record 카드 목록 표시 | 홈 |
| 2 | 기록 카드 탭 | 해당 Record의 상세 기록지 뷰어로 진입 | 기록지 뷰어 |
| 3 | 카테고리별 카드 확인 | 섹션별 불릿 내용 표시 | 기록지 뷰어 |
| 4 | `<` 뒤로가기 | 홈 복귀 | 홈 |

### 2-B. 과거 기록 조회 (캘린더)

| 단계 | 사용자 행동 | 시스템 반응 | 다음 화면 |
|------|------------|-----------|---------|
| 1 | 홈 상단 `캘린더` 토글 탭 | 월 달력 펼쳐짐. 기록 있는 날짜 아래 파란 점, 오늘은 파란 원 | 홈 (캘린더 확장) |
| 2 | 원하는 날짜 탭 | 선택한 날짜로 홈 화면 전환 (오늘의 기록 영역이 해당 날짜 기록으로 대체) | 홈 (해당 날짜) |
| 3 | 기록 카드 탭 | 기록지 뷰어 진입 | 기록지 뷰어 |
| 4 | 헤더의 `<` / `>` 화살표 탭 | 이전/다음 **월**로 이동 (월 단위 네비게이션) | 홈 (이동한 월의 캘린더) |

**핵심 규칙**
- 기록이 없는 날짜: "아직 오늘 기록이 없어요" 표시. **해당 날짜로 이동 후에도 기록 작성 가능** → 기록 시 해당 날짜(recorded_date)로 저장됨.
- 캘린더 점 표시 조회는 월 단위로 API 호출 (성능 최적화).
- 캘린더 헤더 `<` / `>` 는 **월 단위 이동** (일 단위 이동 아님).

## 3. 기록 수정 흐름

작성한 Record를 편집하는 흐름. 섹션/불릿 단위의 세밀한 편집을 지원.

### 3-A. 기록 수정 진입

| 단계 | 사용자 행동 | 시스템 반응 | 다음 화면 |
|------|------------|-----------|---------|
| 1 | 홈에서 오늘의 기록 카드의 `⋮` 탭 | 바텀시트 표시: `기록 수정하기` / `삭제하기` | 홈 (바텀시트) |
| 2 | `기록 수정하기` 탭 | 기록지 수정 화면으로 진입 (섹션 카드 전체 클릭 가능 상태) | 기록지 수정 |

### 3-B. 섹션(카테고리) 편집

| 단계 | 사용자 행동 | 시스템 반응 | 다음 화면 |
|------|------------|-----------|---------|
| 1 | 수정하려는 섹션 카드 탭 | 해당 섹션의 편집 바텀시트 오픈 (카테고리명 + 불릿 리스트) | 기록지 수정 (바텀시트) |
| 2 | 카테고리명 수정 또는 불릿 내용 수정 | 편집 가능 상태 (로컬 임시 상태) | (동일) |
| 3 | 불릿 옆 🗑️ 탭 | 해당 불릿 즉시 삭제 (모달 없음, 로컬 상태) | (동일) |
| 4 | `+ 기록 추가하기` 탭 | 새 불릿 입력 라인 추가 | (동일) |
| 5 | 카테고리명 옆 🗑️ 탭 | 경고 모달: "'XX' 항목을 삭제하시겠어요? 함께 있는 상세 내용도 함께 삭제됩니다" | (모달) |
| 5-a | 모달 `삭제` 탭 | 섹션 전체 삭제 (로컬 상태) | 기록지 수정 (섹션 제거됨) |
| 5-b | 모달 `취소` 탭 | 모달 닫힘, 변경 없음 | 기록지 수정 (바텀시트) |
| 6 | 바텀시트 `저장` 탭 | 해당 섹션 편집 내용을 메인 화면 상태에 반영 | 기록지 수정 |
| 7 | 바텀시트 `취소` 탭 | 해당 섹션 편집 내용 모두 폐기, 원본으로 복구 | 기록지 수정 |

### 3-C. 섹션 추가

| 단계 | 사용자 행동 | 시스템 반응 | 다음 화면 |
|------|------------|-----------|---------|
| 1 | 하단 `추가하기` 버튼 탭 | 바텀시트: "추가할 항목명을 입력해 주세요" | 기록지 수정 (바텀시트 1) |
| 2 | 카테고리명 입력 후 `다음` | 바텀시트: "항목에 기록할 내용을 입력해 주세요" | 기록지 수정 (바텀시트 2) |
| 3 | 내용 입력 후 `저장` | 새 섹션이 기록지 하단에 추가됨 (로컬 상태) | 기록지 수정 |

### 3-D. 최종 저장

| 단계 | 사용자 행동 | 시스템 반응 | 다음 화면 |
|------|------------|-----------|---------|
| 1 | 하단 `저장하기` 탭 | DB UPDATE (Record.sections 덮어쓰기) | 기록지 뷰어 또는 홈 |

**핵심 규칙**
- 바텀시트 `저장` = 메인 화면 반영 (임시). 하단 `저장하기` = DB 커밋.
- 하단 `저장하기` 안 누르고 이탈 시 모든 편집 폐기 (MVP는 unsaved changes 경고 없이 단순 처리).
- AI 생성 섹션과 유저 추가 섹션 모두 편집/삭제 가능 (구분 없음).

### 3-E. 기록 삭제

| 단계 | 사용자 행동 | 시스템 반응 | 다음 화면 |
|------|------------|-----------|---------|
| 1 | 기록 카드 `⋮` → `삭제하기` 탭 | 바텀시트: "'XX' 기록 삭제하기 — 오늘 기록한 내용에 대해 삭제합니다. 루틴은 삭제되지 않습니다" | 홈 (삭제 모달) |
| 2 | `삭제` 탭 | 해당 Record를 DB에서 삭제 (hard delete), 홈 갱신 | 홈 |
| 2-a | `취소` 탭 | 모달 닫힘, 변경 없음 | 홈 |

## 4. 기록 대상 선택 흐름 (루틴 생성)

신규 루틴을 만드는 3단계 온보딩 흐름. 가입 직후 또는 홈에서 언제든 진입 가능.

| 단계 | 사용자 행동 | 시스템 반응 | 다음 화면 |
|------|------------|-----------|---------|
| 1 | 홈 상단 `+ 루틴 추가` 탭 | 루틴 생성 1단계 화면 진입 | 루틴 생성 1단계 |
| 2 | "누구의 질병을 기록할까요?" — 대상 선택 | 선택지: 본인 / 부모님 / 배우자 / 자녀 / 친구 / 기타 | 루틴 생성 1단계 |
| 3-a | 본인~친구 중 선택 → `다음` | 2단계로 진입 | 루틴 생성 2단계 |
| 3-b | `기타(직접 입력)` 선택 | 텍스트 입력창 표시 (예: "반려견", "할머니" 등) | 루틴 생성 1단계 (기타 상태) |
| 3-b-1 | 커스텀 이름 입력 → `다음` | 2단계로 진입 (subject_custom_name 저장) | 루틴 생성 2단계 |
| 4 | "OOO에 대해 알려주세요" — 기본 정보 입력 | 성별 / 생년월일 / 키 / 체중 입력 필드 표시 | 루틴 생성 2단계 |
| 5 | 모든 필드 입력 → `다음` | 3단계로 진입 | 루틴 생성 3단계 |
| 6 | "무엇을 기록해 볼까요?" — 기록지 제목 입력 | 텍스트 입력 (예: "역류성 식도염") | 루틴 생성 3단계 |
| 7 | 제목 입력 → `다음` | Routine DB에 저장 | 루틴 생성 완료 |
| 8 | "기록 루틴을 만들었어요" → `확인` | 홈 복귀 (새 루틴 카드 "기록 루틴" 영역에 표시) | 홈 |

**핵심 규칙**
- 각 단계의 `다음` 버튼은 모든 필수 필드 입력 전까지 비활성.
- 뒤로가기(`<`) 가능. 입력 내용은 단계 간 유지 (로컬 상태).
- 중도 이탈 시 저장 없음 (DB 커밋은 7단계 완료 시점).
- 대상 유형에 관계없이 2단계의 기본 정보 필드는 동일. (반려동물도 동일 적용)

## 5. STT 사용 흐름

음성으로 기록을 남길 때의 Whisper 연동 흐름.

| 단계 | 사용자 행동 | 시스템 반응 | 다음 화면 |
|------|------------|-----------|---------|
| 1 | 기록 작성 화면 중앙 마이크 아이콘 탭 | 마이크 권한 확인 (최초 1회 시스템 다이얼로그) | 기록 작성 |
| 1-a | 권한 거부 | 안내 토스트: "음성 입력을 사용하려면 마이크 권한이 필요해요", 텍스트 입력으로 대체 유도 | 기록 작성 (텍스트 모드) |
| 2 | 권한 허용 → 녹음 시작 | 마이크 아이콘이 정사각형 `중지` 버튼으로 변경, 시각적 피드백 애니메이션(움직이는 점/파형) 표시 | 기록 작성 (녹음 중) |
| 3 | 말하기 | 녹음 진행 (로컬에 오디오 버퍼 저장) | 기록 작성 (녹음 중) |
| 4 | 중지 버튼 탭 | 녹음 종료 → 오디오 파일을 Whisper API로 전송 | 기록 작성 (변환 중) |
| 5 | 대기 (수 초) | 변환 완료 → 결과 텍스트를 하단 채팅창에 표시 (편집 가능) | 기록 작성 (검토) |
| 6 | 필요시 텍스트 수정 | 유저가 오타/오인식 직접 교정 | 기록 작성 (검토) |
| 7 | 전송 버튼(↑) 탭 | AI 분석 흐름(섹션 6)으로 이어짐 | (다음 흐름) |

**중간 이탈 (녹음 중)**

| 단계 | 사용자 행동 | 시스템 반응 | 다음 화면 |
|------|------------|-----------|---------|
| A | 녹음 중 `<` 뒤로가기 탭 | 모달: "오늘의 기록 종료하기 — 기록을 종료하시겠어요? 지금 종료하면 저장되지 않아요" | 기록 작성 (모달) |
| A-1 | `종료` 탭 | 녹음 중단, 버퍼 폐기, 홈 복귀 | 홈 |
| A-2 | `취소` 탭 | 모달 닫힘, 녹음 상태 유지 | 기록 작성 (녹음 중) |

**핵심 규칙**
- MVP에서는 **녹음 중지 후 일괄 변환**. 실시간 스트리밍 STT는 구현하지 않음.
- 녹음 중 시각 피드백은 "말이 잘 잡히고 있다"는 심리적 안정감을 주는 용도. 실제 음성 인식과 무관.
- Whisper 응답 시간은 녹음 길이에 비례. 긴 녹음은 로딩 표시 필수.
- 마이크 아이콘은 녹음 완료 후에도 화면에 남아, 필요시 이어서 녹음하거나 재녹음 가능.

## 6. AI 분석 흐름

유저가 확정한 텍스트를 Claude에게 보내 카테고리별 기록지로 정리하는 흐름.

| 단계 | 사용자 행동 | 시스템 반응 | 다음 화면 |
|------|------------|-----------|---------|
| 1 | 기록 작성 화면에서 전송 버튼(↑) 탭 | 로딩 화면 전환: "말씀하신 내용을 기반으로 기록지를 생성할게요" / "열심히 요약하는 중..." | 기록 작성 (분석 중) |
| 2 | 대기 | 백엔드: (1) 유저 텍스트 + 사전 정의 프롬프트 조합 → (2) Claude API 호출 → (3) 응답 JSON 파싱 → (4) 스키마 검증 | (동일) |
| 3 | 대기 | 검증 통과: 카테고리별 섹션 렌더링 → 결과 화면 표시 | 기록지 결과 |
| 4 | 결과 확인 | "기록지를 생성했습니다" 제목 + 섹션 카드 목록 표시 | 기록지 결과 |
| 5 | `기록 완료` 탭 | DB에 Record 최초 저장 (sections 포함) | 저장 완료 화면 |

**분석 실패 시 (섹션 7 참조)**

**핵심 규칙**
- Claude 호출은 백엔드 경유 (프론트에서 직접 호출 금지 — API 키 보호).
- 응답 JSON이 예상 스키마와 다르면 1회 재시도, 재시도도 실패하면 에러 플로우.
- 정의된 카테고리 리스트에 없는 내용도 **"기타" 카테고리로 분류**하여 누락 방지.
- LangSmith로 호출 전 구간 추적 (프롬프트 / 응답 / 소요시간 / 토큰).
- **평균 응답 시간 목표: 5초 이내** (Sonnet 또는 Haiku 모델 사용 권장, Opus는 과함). 입력이 긴 경우 최대 10초까지 허용. 이를 위해 로딩 화면에 "열심히 요약하는 중..." 메시지로 대기 체감 완화.

## 7. 실패 흐름 (에러 시)

각 흐름에서 발생 가능한 주요 에러와 대응.

### 7-A. 카카오 로그인 실패

| 단계 | 사용자 행동 | 시스템 반응 | 다음 화면 |
|------|------------|-----------|---------|
| 1 | `카카오로 시작하기` 탭 | 카카오 OAuth 팝업 실패 또는 네트워크 에러 | 로그인 |
| 2 | - | 토스트: "로그인에 실패했어요. 잠시 후 다시 시도해 주세요" | 로그인 |

### 7-B. Whisper 변환 실패

| 단계 | 사용자 행동 | 시스템 반응 | 다음 화면 |
|------|------------|-----------|---------|
| 1 | 녹음 후 자동 전송 | Whisper API 에러 (타임아웃 / 네트워크 / 변환 실패) | 기록 작성 |
| 2 | - | 토스트: "음성을 텍스트로 바꾸지 못했어요. 다시 시도해 주세요." 녹음 다시 시작 가능 상태로 복귀 | 기록 작성 (초기) |

### 7-C. Claude 분석 실패

| 단계 | 사용자 행동 | 시스템 반응 | 다음 화면 |
|------|------------|-----------|---------|
| 1 | 전송 버튼 탭 후 대기 | Claude API 에러 또는 JSON 파싱 실패 → 1회 자동 재시도 | 기록 작성 (분석 중) |
| 2 | - | 재시도도 실패 → 에러 화면 또는 토스트: "지금은 기록을 정리하기 어려워요. 잠시 후 다시 시도해 주세요" | 기록 작성 (검토 상태로 복귀) |
| 3 | `다시 시도` 탭 | Claude 재호출 | 기록 작성 (분석 중) |

**중요**: 분석 실패 시 유저가 입력한 텍스트(`raw_transcript`)는 **로컬에 유지**되어야 함. 다시 타이핑하게 만들면 UX 치명적.

### 7-D. 기록 저장 실패

| 단계 | 사용자 행동 | 시스템 반응 | 다음 화면 |
|------|------------|-----------|---------|
| 1 | `기록 완료` 탭 | DB 저장 중 에러 (네트워크 / 서버) | 저장 완료 (에러 상태) |
| 2 | - | 토스트: "저장에 실패했어요. 다시 시도해 주세요" + `다시 시도` 버튼 유지 | 기록 작성 (결과 화면) |

### 7-E. 캘린더 조회 실패

| 단계 | 사용자 행동 | 시스템 반응 | 다음 화면 |
|------|------------|-----------|---------|
| 1 | 캘린더 토글 탭 또는 날짜 이동 | 기록 조회 API 실패 | 홈 |
| 2 | - | 해당 영역에 안내: "기록을 불러오지 못했어요" + `새로고침` 버튼 | 홈 (에러 상태) |

### 7-F. 공통 네트워크 단절

| 단계 | 사용자 행동 | 시스템 반응 | 다음 화면 |
|------|------------|-----------|---------|
| 1 | 오프라인 상태에서 API 호출 | 네트워크 에러 감지 | 현재 화면 |
| 2 | - | 공통 토스트: "인터넷 연결을 확인해 주세요" | 현재 화면 |

**핵심 규칙**
- 모든 에러 메시지는 **사용자 언어**로 (기술 용어 금지).
- 데이터 손실 가능성이 있는 에러는 **로컬 상태 유지** + 재시도 버튼 제공.
- 같은 에러 반복 시 3회 이상 실패하면 "1:1 문의" 버튼 노출 고려 (단, MVP에서는 구글폼 링크).
- 모든 에러는 서버 로그로 기록. LangSmith가 AI 호출 에러는 자동 기록.

## 📌 요약

LOOMA의 모든 흐름은 **"루틴 생성 → 기록 작성 → 확인/수정"** 이라는 반복 축을 중심으로 돈다. 위 7개 흐름 중 **1번(기록 생성) / 5번(STT) / 6번(AI 분석)** 이 서로 맞물려 "음성 한 번으로 기록지가 만들어진다"는 이 앱의 핵심 가치를 구현한다. 나머지 흐름은 이 축을 지탱하는 주변 플로우다.
