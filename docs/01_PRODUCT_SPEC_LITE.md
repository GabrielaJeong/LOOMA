# 01_PRODUCT_SPEC_LITE

---

## 🎯 한 줄 정체성

**LOOMA**는 본인·가족·지인·반려동물의 **질병/증상을 루틴 단위로 매일 기록**하는 모바일 앱. 유저가 말(음성)이나 글(텍스트)로 중언부언 쏟아내면, **AI가 사전 정의된 카테고리로 일목요연하게 정리**해서 기록지를 만든다.

**현재 단계**: MVP. 빠르게 동작하는 것을 최우선.

---

## 🧠 핵심 멘탈 모델

> **"운동 루틴 앱처럼, 질병 루틴 앱."**

| 운동 앱 | LOOMA |
|--------|-------|
| "하체 운동" 루틴 생성 | "엄마 고혈압" 루틴 생성 |
| 매일 그 루틴을 수행 | 매일 그 루틴에 기록 |
| 수행 기록이 쌓임 | 일별 기록지가 쌓임 |

- **루틴** = 기록 대상 × 질병/증상 (1:1)
- **기록(Record)** = 특정 루틴의 특정 날짜 기록지
- **같은 루틴을 하루 여러 번 기록 가능** (중복 체크 없음, 카드 여러 개 생성)

## 📦 MVP 범위

### ✅ 포함
- 카카오 OAuth 로그인 / 약관 동의 / 닉네임 입력 / 가입 완료
- 루틴 생성 3단계 (대상 선택 → 기본정보 → 질병명)
- 홈 화면 (날짜 네비게이션, 오늘의 기록, 기록 루틴, 캘린더)
- 음성 기록 (Whisper → Claude)
- 텍스트 기록 (타이핑 → Claude)
- 기록지 수정 (섹션/불릿 단위)
- 기록/루틴 삭제 (영향 범위 경고 포함)
- 캘린더 기반 과거 기록 조회
- 마이페이지 (정보 수정, 알림 설정, 로그아웃, 회원 탈퇴)

### ❌ 제외 (구현 금지)
- 주간/월간 AI 요약지
- 기록 리마인더 / 푸시 알림
- 1:1 문의 기능 (버튼만 존재, 연결 없음)
- 실시간 STT 스트리밍 (중지 후 일괄 변환으로 구현)
- 개인화된 건강 조언·진단 (**의료 조언 절대 금지**)
- 가족 간 공유 / 의료진 공유
- PDF/이미지 내보내기

## 🗄️ 데이터 구조 (개념)

```
User (카카오 계정)
 └─ Patient[] — 기록 대상 프로필 (본인/가족/지인/반려동물)
     └─ Routine[] — 대상 × 질병 (예: "엄마 고혈압")
         └─ Record[] — 날짜별 기록지
             └─ Section[] — 카테고리별 카드 (예: "주요 증상")
                 └─ items[] — 불릿 내용
```

### 핵심 규칙
- **Patient ≠ Routine**: Patient는 순수 프로필(성별/생년월일/키/체중). Routine은 "그 Patient의 특정 질병"을 관리하는 단위.
- **1 Patient : N Routine**: 같은 엄마가 고혈압·당뇨 둘 다 있으면 Patient 1개 + Routine 2개. 엄마 프로필 중복 입력 X.
- **같은 루틴을 하루에 여러 번 기록 가능** → Record가 여러 개 생성됨
- **루틴 삭제해도 과거 Record는 보존** (soft delete, `deletedAt` 사용)
- **Conversation 모델**: 음성 세션 관리용. MVP에서는 1 세션 = 1 Record 단순 매핑. audioUrls는 STT 완료 후 삭제.

### 필드 네이밍
실제 스키마는 **camelCase** 사용 (Mongoose 관례):
- `rawTranscript`, `diseaseName`, `patientId`, `routineId`, `conversationId` 등
- 상세 스키마는 `backend/src/models/` 코드 참조.

### 보안 주의
기록 원문(`rawTranscript`)과 정리된 내용(`sections`, `summary`, `notes`)은 민감정보 → **AES-256 암호화 저장 필수** (Mongoose pre-save 훅 활용).

## 🔁 핵심 반복 흐름

```
[홈] 루틴 카드의 [오늘의 기록 시작하기] 탭
  ↓
[기록 작성] 마이크 탭 → 말 → 중지
  ↓
Whisper API → 텍스트 변환 → 유저 수정 가능
  ↓
[전송] 탭 → Claude API → 카테고리별 정리
  ↓
[기록 완료] 탭 → DB 저장 → 홈 복귀
```

## 🤖 AI / STT 동작 규칙

### Whisper (STT)
- 녹음 **중지 후 일괄 변환** (MVP에서는 실시간 스트리밍 안 함)
- 녹음 중 화면 표시는 **시각적 피드백만** (움직이는 점, 파형 등)
- 변환 결과는 **유저가 편집 가능** → 편집된 최종본을 Claude로 전달

### Claude (AI 정리)
- **입력**: 유저가 확정한 텍스트
- **출력**: JSON. 스키마 고정:
  ```json
  {
    "sections": [
      { "category": "카테고리명", "items": ["불릿1", "불릿2"] }
    ]
  }
  ```
- **카테고리 규칙**:
  - 사전 정의된 카테고리 마스터 리스트(약 20개 예정)에서만 선택
  - 어디에도 딱 맞지 않는 내용은 **"기타" 카테고리로 분류** (누락 금지)
  - 해당되는 카테고리만 출력, 없는 카테고리는 생략
- **프롬프트 상세와 카테고리 마스터 리스트**는 `04_AI_PROMPTS.md`에 정의 (별도 작성 예정)

### LangSmith
- Claude 호출 전 구간 추적
- 추적 항목: 응답 시간, 성공/실패, 프롬프트, 응답 JSON

## 🛡️ 개발 시 반드시 지킬 원칙 (하지 말 것)

1. **의료 조언 생성 금지**. Claude 응답에 "~해야 합니다", "~병 같습니다" 같은 진단·처방은 절대 금지. 프롬프트에서 명시적으로 차단.
2. **raw_transcript와 sections는 암호화 없이 저장 금지**. 민감정보.
3. **Claude 응답을 그대로 DB에 저장하지 말 것**. JSON 파싱 실패 대비 검증 레이어 필수.
4. **루틴 삭제 시 과거 Record 삭제 금지**. Routine에 `is_deleted` 플래그만 세움 (soft delete).
5. **중복 기록 병합 로직 구현 금지**. MVP는 같은 루틴 하루 여러 번 기록 시 카드 여러 개 생성하는 단순 구조.
6. **기록 작성 중 이탈 시 저장 금지**. 음성/텍스트 입력 중 뒤로가기 → 경고 모달 → [종료] 시 드롭.
7. **카카오 OAuth 외 로그인 구현 금지**. 이메일/비밀번호 X.

| 개념 | 코드 필드명 | UI 표기 |
