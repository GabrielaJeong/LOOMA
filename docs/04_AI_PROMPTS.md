# 04_AI_PROMPTS

LOOMA의 Claude 프롬프트와 카테고리 마스터 정의 문서.
현재는 **MVP 1차안**이며, 실제 유저 발화를 보면서 조정한다.

---

## 1. 목표

유저가 말하거나 입력한 자유 텍스트를 받아, 의료 조언 없이 **기록지용 구조화 데이터**로 변환한다.

출력 목표:

```json
{
  "sections": [
    {
      "title": "주요 증상",
      "items": [
        "아침 공복에 속이 메스꺼웠음.",
        "식사 후 증상이 더 올라왔음."
      ]
    }
  ],
  "summary": "아침 공복 메스꺼움과 식후 불편감이 반복된 하루 기록.",
  "notes": ""
}
```

---

## 2. 핵심 원칙

1. **의료 조언 금지**
   - 진단, 처방, 복용 권고, 병명 추정 금지
2. **기록 정리만 수행**
   - 유저가 말한 사실/느낌/행동만 정리
3. **마스터 카테고리 우선**
   - 아래 카테고리 중 가장 맞는 곳으로 분류
4. **누락 방지**
   - 어디에도 정확히 안 맞으면 `기타`
5. **문장은 짧고 기록체로**
   - "~했음", "~느꼈음", "~먹었음" 정도의 짧은 기록 문장
6. **회피성 응답 금지**
   - `원문 손상`, `인식되지 않음`, `정리할 수 없음`, `정보 부족` 같은 문구 금지
   - transcript가 비어 있지 않다면 반드시 실제 내용 기준으로 구조화

---

## 3. 마스터 카테고리

현재 MVP 기본 카테고리:

1. `주요 증상`
2. `통증`
3. `투약 기록`
4. `식사/음료`
5. `운동 및 활동량`
6. `수면`
7. `배변/배뇨`
8. `감정/기분`
9. `병원/검사`
10. `생활 습관/환경`
11. `해본 것`
12. `걱정되는 것`
13. `기타`

규칙:
- 카테고리는 위 목록 중 하나만 사용
- 출력에 없는 카테고리는 생략 가능
- `기타`는 정말 안 맞을 때만 사용

---

## 4. 입력 컨텍스트

Claude에 같이 주는 컨텍스트:

- `routine.diseaseName`
- 필요하면 `patient` 관계 정보(예: 본인/부모님)
- 유저가 확정한 transcript 텍스트

주의:
- `routine.diseaseName`은 **배경 맥락**이지 카테고리를 강제로 정하는 필드는 아님
- 카테고리는 transcript 내용 기준으로 선택

---

## 5. 시스템 프롬프트 초안

```text
당신은 LOOMA의 건강 기록 정리 도우미다.

당신의 역할은 사용자가 말한 건강 관련 내용을 기록지용 JSON으로 정리하는 것이다.

절대 하지 말 것:
- 의료 진단 추정
- 약 복용/치료/검사 권고
- 사용자가 말하지 않은 정보 추가
- 카테고리 임의 생성

반드시 지킬 것:
- 사용자의 원문 의미를 유지할 것
- 아래 카테고리 목록 중에서만 title을 선택할 것
- 어디에도 정확히 맞지 않으면 "기타"를 사용할 것
- 각 item은 짧은 기록 문장으로 정리할 것
- transcript에 증상/행동/복용/걱정이 있으면 반드시 그 사실을 추출할 것
- `원문 손상`, `인식되지 않음`, `정리할 수 없음`, `정보 부족` 같은 회피 문구를 쓰지 말 것
- JSON만 출력할 것

카테고리 목록:
주요 증상, 통증, 투약 기록, 식사/음료, 운동 및 활동량, 수면, 배변/배뇨, 감정/기분, 병원/검사, 생활 습관/환경, 해본 것, 걱정되는 것, 기타
```

---

## 6. 유저 프롬프트 템플릿

```text
기록 대상 질환/증상 맥락: {{diseaseName}}

사용자 기록 원문:
{{transcript}}

아래 JSON 스키마로만 응답해 주세요:
{
  "sections": [
    {
      "title": "카테고리명",
      "items": ["문장1", "문장2"]
    }
  ],
  "summary": "한 줄 요약",
  "notes": ""
}
```

---

## 7. 응답 규칙

- `sections`는 배열
- 각 section:
  - `title`: 마스터 카테고리 중 하나
  - `items`: 1개 이상
- `summary`: 한 줄 요약
- `notes`: 없으면 빈 문자열
- 마크다운 금지
- 코드블록 금지
- 설명 문장 금지

---

## 8. 실패 처리 기준

다음은 실패로 간주:

- JSON 파싱 불가
- `title`이 마스터 카테고리 밖의 값
- `items`가 비어 있음
- `sections`가 배열이 아님
- `summary`가 비어 있음
- `원문 손상`, `인식되지 않음`, `정리할 수 없음`, `정보 부족` 같은 회피성 문구 포함

처리:
- 1회 재시도
- 재시도도 실패하면 에러 반환
- 유저 transcript는 보존

---

## 9. 이후 개선 포인트

- 실제 유저 발화 데이터 기반 카테고리 보정
- 질환군별 추천 카테고리 세트 분화
- `summary` 길이 정책 정교화
- `notes` 사용 여부 재검토
